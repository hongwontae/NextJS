1. 배포 환경
1-1. npm run build 명령어를 통해 배포 환경에서 동작할 수 있게 해줍니다.
1-2. npm run build가 마무리되면 npm start를 통해 배포 환경을 실행할 수 있습니다.

1-3. 기본적으로 next.js의 배포 환경에서는 모든 페이지를 사전 렌더링하여 전달합니다.
=> 이런 경우 빌드 타임 한 번만 렌더링되어 데이터 추가나 업데이트 효과가 반영되지 않습니다.
=> 또한 데이터가 변동하더라도 클라이언트가 캐시된 HTML을 재사용합니다.
1-4. revaildatePath()를 통해 유효성 재검사 함수를 호출하여 해결할 수 있습니다.
=> 특정 경로에 속하는 캐시를 재평가합니다.
=> revaildatePath('path', 'page or layout')
=> page일 경우 해당 경로에 존재하는 page.js 하나만, layout는 중첩된 모든 page

1-5. 배포 환경에서는 public 폴더에 관여하지 않습니다.
=> AWS, Image 클라우드 서비스를 통해 파일을 저장하는 해야 동작합니다.


2. 개발환경과 배포환경의 캐싱의 차이
2-1. 개발환경
=> fetch 호출에 대해 기본적으로 캐시가 비활성화되거나 제한적으로 동작합니다.
=> 모든 요청에서 항상 새로운 데이터를 가져옵니다.
=> 캐싱된 페이지가 아니라 새 데이터를 반영한 HTML을 반환합니다.
=> cache: 'force-cache', cache: 'no-store', next: { revalidate: n } 등의 옵션을 설정해도,
 개발 환경에서는 항상 최신 데이터를 가져옵니다.

2-2. 배포환경
=> fetch 호출에서 캐싱 전략(force-cache, revalidate, no-store)이 설정된 대로 동작합니다.
=> 19. NextJS Cache처럼 동작합니다.
