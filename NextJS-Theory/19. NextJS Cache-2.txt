1. Full Route Cache
=> App Router에서 경로(페이지) 단위로 전체 HTML 응답을 캐싱하는 전략입니다. 

1-1. 특징
1. HTML 캐싱
=> 페이지 전체를 캐싱하며, 각 요청마다 동일한 HTML 응답을 반환합니다.

2. 캐시 제어
=> 캐시 유효 기간을 설정할 수 있습니다.
=> revalidation 값에 따라 캐시된 HTML을 주기적으로 갱신합니다.

3. 빠른 응답
=> CDN과 결합하면 전 세계적으로 빠르게 정적 콘텐츠를 제공할 수 있습니다.


1-2. 사용 방법
export const revalidation 사용
=> revalidation을 설정하여 전체 페이지 데이터을 일정 시간 간격으로 재검증하도록 지정합니다.
=> 설정한 시간 동안 동일한 HTML이 캐시됩니다.
=> revalidation 값이 설정되면, 페이지는 정적 HTML(ISR)로 생성되고 캐시를 갱신하는 방식으로 동작합니다.


*** CDN
=> 전 세계에 분산된 서버 네트워크를 통해 콘텐츠(예: HTML, CSS, JS, 이미지, 비디오 등)를
 빠르고 효율적으로 제공하는 기술 또는 인프라입니다.
=> 사용자와 가까운 서버에서 콘텐츠를 제공하여 지연 시간을 줄이고 웹 페이지 로딩 속도를 개선합니다.
=> Next.js의 Full Route Cache 전략에서 말하는 CDN은, 서버가 생성한 HTML을 캐싱하여 CDN을 통해
 제공하는 것을 의미합니다.



2. Router Cache
=> 클라이언트 측에서 페이지 전환 시 HTML을 캐시하여, 동일한 페이지를 다시 요청할 때 서버로부터
 새롭게 HTML을 가져오는 대신 캐시된 HTML을 빠르게 로드하는 방식입니다.

2-1. 작동방식
1. 클라이언트 측 캐싱
=> Router Cache는 클라이언트 측에서 URL을 기준으로 특정 페이지의 HTML을 캐시합니다.
=> 클라이언트가 동일한 URL을 다시 요청할 경우, 캐시된 HTML을 사용하여 빠르게 페이지를 렌더링합니다.

2. 캐시된 HTML을 사용하는 시점
=> 한 번 렌더링된 페이지의 HTML이 캐시되면, 이후 같은 페이지를 요청할 때는 
서버에 요청하지 않고 캐시된 HTML을 즉시 반환합니다.
=> 페이지의 내용이나 데이터가 변경될 경우, 캐시된 HTML을 갱신하거나 revalidation 옵션을
 통해 일정 주기마다 페이지를 새로 고칠 수 있습니다.



3. export const dynamic
3-1. export const dynamic = 'true';
=> 사용자가 페이지를 요청할 때마다 최신 데이터를 반영하여 HTML을 반환합니다.

3-2. export const dynamic = 'false';
=> dynamic = 'false'로 설정하면, 페이지는 정적으로 생성되며, 서버 요청이 있을 때마다 동일한 HTML을 반환합니다. 

3-3. export const dynamic = 'auto'; (default)
=> 서버에서 데이터를 요청하는 부분이 있다면 dynamic = true
=> 페이지 로드된 후 클라이언트 측에서 데이터 요청 있다면 dynamic = true
=> 정적 데이터만 사용하는 경우 dynamic = false
