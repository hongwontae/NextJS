1. middleware
=>  요청(Request)과 응답(Response) 사이에서 동작하는 코드를 작성하여 
 요청을 처리하거나 변형할 수 있는 강력한 기능입니다.


2. middleware의 특징
2-1. 요청 기반 처리: 요청이 서버에 도달했을 때 실행됩니다.
2-2. 파일 기반 구성: 프로젝트의 루트 디렉토리에 middleware.js 또는 middleware.ts 파일로 정의됩니다.
2-3. Edge Function 기반: 빠른 응답 속도를 위해 Edge Network에서 실행됩니다.
2-4. 유연한 제어: 요청을 수정, 리다이렉트, 응답 차단, 헤더 변경 등이 가능합니다.


3. middleware의 동작 원리
3-1. 클라이언트의 요청이 들어오면 Middleware가 요청을 가로챕니다.
3-2. 요청(Request) 객체를 기반으로 논리를 실행합니다.
3-3. 요청을 허용(NextResponse.next()), 수정, 리다이렉트, 또는 차단할 수 있습니다.


4. middleware 생성 및 기본 사용법
4-1. middleware.js or middleware.ts 파일을 루트 디렉토리에 생성합니다.
4-2. 이후 요청을 차단하거나 리다이렉트 로직을 사용합니다.


5. NextResponse 객체
=> Middleware에서 응답을 생성하거나 요청을 수정할 때 사용하는 객체입니다.

5-1. NextResponse.next(): 요청을 처리하도록 다음 단계로 넘깁니다.
5-2. NextResponse.redirect(): 요청을 특정 URL로 리다이렉트합니다.
5-3. NextResponse.rewrite(): 요청 URL을 다른 URL로 변경합니다.
5-4. Response 객체: 새 응답을 생성합니다.


6. request 객체
=> request 객체는 클라이언트 요청에 대한 정보를 담고 있으며, 다양한 속성에 접근할 수 있습니다.

6-1. request.nextUrl: URL 객체로, 요청 URL의 정보를 제공합니다.
6-2. request.headers: 요청 헤더.
6-3. request.method: HTTP 메서드(GET, POST 등).
6-4. request.ip: 클라이언트 IP 주소.


7. 동적 경로 처리
=> Middleware는 동적 경로를 활용하여 특정 요청만 처리할 수 있습니다.
=> export const config = {
  matcher: ['/admin/:path*', '/dashboard/:path*'], // 특정 경로에만 Middleware 적용
};
=> matcher를 통해 Middleware가 적용될 경로를 지정할 수 있습니다.
