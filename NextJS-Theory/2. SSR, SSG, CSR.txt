1. 서버 사이드 렌더링
=> 요청 시 서버에서 HTML을 생성하여 브라우저에게 전달하는 방식입니다.

1-1. 동작 흐름
1. 사용자가 URL을 요청하면 서버에서 해당 페이지의 React 컴포넌트를 렌더링합니다.
2. 필요하면 데이터베이스나 API 호출을 통해 데이터를 가져옵니다.
3. 서버는 완성된 HTML을 브라우저에 전달합니다.
4. 브라우저는 HTML을 렌더링하고, JavaScript가 로드되면 React가 하이드레이션을 수행합니다.

1-2. 장점
=> SEO에 적합
=> 빠른 초기 화면 로드

1-3. 단점
=> 서버 부하 증가
=> 네트워크 대기 시간 길어질 수 있음


2. 정적 사이트 생성
=> 빌드 시 미리 HTML을 생성하고, 요청 시 이를 바로 제공하는 방식입니다.

2-1. 동작 흐름
1. 애플리케이션 빌드 시 정적 HTML 파일을 생성합니다.
2. 사용자가 페이지를 요청하면, 서버는 미리 생성된 HTML 파일을 즉시 제공.
3. 브라우저에서 React가 하이드레이션을 통해 동작.

2-2. 장점
1. 빠른 로드 시간 (미리 생성된 HTML 제공).
2. 서버 부하 감소.

2-3. 단점
동적 데이터가 필요한 경우 실시간 데이터를 반영하기 어려움


3. 클라이언트 사이드 렌더링
=>  브라우저에서 JavaScript가 HTML을 생성하고, 데이터를 가져와 렌더링하는 방식입니다.

3-1. 동작 흐름
1. 브라우저가 빈 HTML 파일과 JavaScript 번들을 다운로드.
2. JavaScript가 실행되어 React가 초기 렌더링을 수행.
3. 필요한 데이터를 클라이언트에서 API로 요청하고, 데이터를 받아 화면에 렌더링.

3-2. 장점
1. 인터랙티브한 UI 구현에 적합.
2. 페이지 이동 시 빠른 사용자 경험 제공.

3-3. 단점
1. SEO에 불리 (초기 HTML에 콘텐츠가 없음).
2. 초기 로드 시간이 느릴 수 있음.
