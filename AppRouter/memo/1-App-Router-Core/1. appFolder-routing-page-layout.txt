1. NextJS app Folder
=> 파일 기반 라우팅을 시작하는 진입점입니다.
=> page.js는 현 라우팅의 컴포넌트입니다. (app 폴더의 root page.js는 초기 화면입니다. 하나만 존재해야 함)
=> layout.js는 현 라우팅의 컴포넌트를 감싸는 컴포넌트입니다. 
(layout 페이지는 app 폴더에 하나는 반드시 존재해야합니다. 주로 root), (html, body 태그는 필수입니다.)


2. 파일 라우팅
=> app 폴더에서 폴더를 생성하고 이름을 붙이면 그 자체로 경로가 됩니다.
=> 그리고 해당 폴더의 root에는 하나의 page.js만 존재해야 합니다.


3. <a> 태그와 next/link <Link> 컴포넌트
3-1. NextJS 페이지 내에서 단순 a 태그를 사용해서 페이지 전환을 시도하면
 완전히 새로운 페이지를 받아옵니다. -> 싱글 페이지 어플리케이션을 벗어나는 행위입니다.
3-2. next/link의 <Link>를 사용하면 싱글 페이지 어플리케이션에 머물게하는 
 클라이언트 사이드 내비게이션으로 이동합니다.


4. layout.js
4-1. page.js를 감싸는 컴포넌트입니다.
4-2. props로 children을 받는데 children이 page.js입니다.
4-3. export const metadata : {}를 통해서 head 태그에 들어가는 metadata를 설정할 수 있습니다.
4-4. app 폴더 전체에 걸쳐 layout 한 개는 반드시 필요하며 여기에는 html, body 태그가 필수적입니다.


5. app folder root에 icon이라는 image
=> favicon으로 인식되어 아이콘으로 보입니다. (웹 위에 아이콘)
