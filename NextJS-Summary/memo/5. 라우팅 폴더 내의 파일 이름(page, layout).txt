1. page.js
=> 해당 라우트에 해당하는 page입니다.
=> 해당 page.js가 렌더링됩니다.


2. layout.js
=> 해당 page.js의 레이아웃입니다. 

2-1. children props를 사용해서 page.js를 표현해야 합니다. => 필수적
2-2. 부모 라우트에 layout.js는 하위 라우트까지 layout합니다.
2-3. export const metadata = {title : '', description : ''...}를 통해 메타데이터를 추가할 수 있습니다.
=> 이 떄 부모 라우트 layout를 포함하는 하위 라우트 page.js도 공유합니다. 다만 하위 layout에 metadata가 존재한다면
그것을 우선시 합니다.
=> page.js에서도 export const metadata={}를 통해 구현할 수 있습니다.
2-4. <html>, <body> 태그가 없어도 되지만 안정적이고 큰 제어권을 가지기 위해서 명시합니다.
=> next.js가 내부적으로 HTML 문서 구조를 자동으로 생성합니다.
2-5. layout.js에서 css 파일을 import하면 해당 레이아웃이 적용되는 컴포넌트들이 적용됩니다.


3. icon.png
=> NextJS에서 favicon으로 사용되는 파일명입니다.


4. loading.js
4-1. 페이지나 레이아웃이 데이터를 가져오거나 렌더링될 준비가 될 떄까지 로딩상태를 표시하는 파일입니다.

4-2. 영향
1. 기본적으로 loading.js는 layout의 로딩 상태를 기다리는 역할입니다.
2. 폴더 내부에 loading.js, page.js 두 개만 존재한다면 loading.js는 하위 경로에 전파되지 않고 해당 폴더의 page.js
만 적용합니다.
3. 폴더 내부에 loading.js, page.js, layout.js가 존재한다면 loading.js가 해당 폴더 + 하위 경로까지 전파됩니다.
4. 상위 loading.js와 하위 loading.js가 존재할 떄 하위에서는 하위 loading.js를 우선시 합니다.

4-3. 기본 작동 방식
=> loading.js는 자동으로 감지되며, React의 Suspense가 트리거될 때 Next.js가 이를 실행합니다.
=> 비동기 데이터 로딩 또는 페이지 전환 동안 해당 컴포넌트가 렌더링됩니다.


5. error.js
5-1. 클라이언트 측에서 발생한 JavaScript 오류, 서버 측에서 발생한 에러(예: API 호출 오류, 데이터베이스 연결 오류 등), 
네트워크 오류 등 다양한 종류의 에러를 처리할 수 있습니다.

5-2. 'use client' 지시어를 사용해야 합니다. 클라이언트 에러 + 서버 에러 둘 다 잡기 위해서..

5-3. app에 error.js는 전역적으로 처리하고 폴더 내부의 error.js는 해당 폴더와 하위 경로를 담당합니다.

5-4. error.js는 page.js에서 throw로 던진 error 


6. not-found.js
6-1. 사용자가 요청한 URL이 존재하지 않을 때, 즉 404 Not Found 상태에서 보여줄 커스텀 페이지입니다.

6-2. not-found.js는 기본적으로 클라이언트 측 렌더링(CSR)으로 작동합니다. 

6-3. app내의 not-found는 전역적으로 처리, 폴더 내부에 있을 때는 error.js 처럼 동작합니다.

6-4. 동적 라우트의 경우 해당 url이 존재하지 않더라도 Next.js가 알 수 없습니다.
=> 그렇기에 not-found.js가 아니라 런타임 에러가 던져집니다.
=> url이 옳지 않다면 notFound()를 호출하여 not-found.js로 향하게 코드를 작성해야 합니다.
